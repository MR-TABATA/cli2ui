# 追加アプリの差し込み口 — 仕様

状態: ①②③⑤ 実装済 / ④ 未実装 / 作成: 2026-09-29

## 目的

コアが名前を知らないまま、別のパッケージ(Django アプリ)を cli2ui に差し込めるようにする汎用の口。
コアには「追加アプリを足す」仕組みだけを置き、差し込まれるものの性質には触れない。

## 部品

### ① `CLI2UI_EXTRA_APPS`(環境変数)
- カンマ区切りのアプリのモジュール名を `INSTALLED_APPS` の末尾に足す。未設定なら何も起きない。
- 書式は小文字の識別子のドット区切りだけ(`pkg` / `pkg.sub`)。`AppConfig` のクラス名を含む指定は拒否する。
- 見つからないモジュールは**黙って無視せず起動時にエラー**。重複や既に入っているアプリは足さない。
- pip で入れただけでは有効にならない(自動発見はしない)。明示した名前だけが有効。

### ② URL の取り込み
- 追加アプリに `urls` モジュールがあれば取り込む。コアの URL の**後ろ**に足すので、コアの URL は上書きされない。
- `urls` が無いアプリは黙って飛ばす(URL を持たないアプリもある)。`urls` の中のエラーは握りつぶさない。

### ③ 機能の制限 `core.features.require(key)`
- view を守るデコレータ。機能が有効でなければ 404。追加アプリの view はこれで edition を守る。

### ④ ナビの差し込み — 未実装(拡張に画面ができてから)
- `features.register(key, edition, nav_template=...)` で機能が自分のボタン用テンプレートを申告し、
  コアのナビは有効な機能のテンプレートを順に描画する。コアは差し込まれるものの名前を知らない。

### ⑤ hosted モードとの関係 — ✅ 実装済(feature/extra-apps-hosted)
- hosted では、追加アプリの URL のうち GET 以外で、対応表にも許可にも載っていないものを既定で拒否する。
- 追加アプリが `hosted.declare_capability(url_name, 機能名[, 説明])` で申告した URL は、その機能の許可に従う。組み込みの機能名でも、説明付きの新しい機能名でもよい。コアのルート名は申告できない(弱められない)。
- 追加アプリのルートかどうかは、view のモジュール名と、申告済みのルート名の両方で判定する(デコレータが `__module__` を落としても漏れない)。
- 忘れても「開く」ではなく「閉じる」側に倒れる。

## 決定事項
- 名前は `CLI2UI_EXTRA_APPS`。pip の自動発見(entry points)はしない。
- `planner_lab` は今回は触らない(動いているものを載せ替えない)。

## 検証
- 書式の検証・重複・見つからないモジュール・URL の取り込み順・`require` の 404/通過を単体テストで確認。
- 実機: 空のダミーアプリで起動、環境変数の誤記で起動エラーになること。
